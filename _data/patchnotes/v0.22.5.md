## v0.22.5: Smoother Enemies, Lighter Crowds, Safer Releases [Patch]

Enemies move the way other players do now. NPCs are drawn along their exact server path a few frames behind real time, the same scheme players got in June, instead of being smoothed toward their last reported spot: no overshoot when one stops, and the delay each client uses is measured from its own connection rather than assumed.

The server does less per enemy and per player, measured on a 40-bot swarm: 10% less CPU per player, enemy AI down a fifth, enemy replication down a quarter.
- Enemy replication read its data through slow name lookups and, because four variables were never declared, re-sent every enemy every time whether it had moved or not. Both fixed; idle enemies no longer cost bandwidth.
- Enemies look for a target ten times a second instead of thirty.
- In crowds, players farther than a screen away update at a third of the rate, and the six packets a newcomer needed per visible player are now one.
- Loot and orb ownership scans and stat syncs are spread across ticks instead of landing on one.

Releases are guarded. A deploy now stops if any map bakes a tile it cannot draw (the bug that put holes in Muscle Tower for eleven days), and when the movement code changed, a bot runs the tight-corner and combat courses at 250 ms ping first and the release fails if prediction got worse.

Your client now reports its own script errors to the server (deduplicated, a few lines at most), so a bug that only happens on your machine is visible without asking for a log. The server writes a daily error digest.

Also: load-test bots no longer overwrite the real client's log files, and a command-line login exists for measurement runs.
